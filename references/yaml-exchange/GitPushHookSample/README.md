# GitPushHookSample（プッシュのフックのサンプル）

ND のプロジェクトと YAML を同じリポジトリで管理するときに使う、Git の pre-push フックのサンプルです。プッシュの前に、プロジェクトと YAML がそろっているかを CLI（`yamlexchange`）で確かめ、片方だけが変わっていれば、もう片方をそろえます。

## 何をするか

1. 今いないブランチをプッシュしようとしているか、プロジェクトか YAML のフォルダにコミットしていない変更があれば止めます（検査は作業コピーで行うため）。
2. `validate` で YAML の書き方を検査します。誤りがあれば止めます。
3. `diff` でプロジェクトと YAML を比べます。差分が無ければ、そのままプッシュします。
4. 差分があれば、プッシュするコミット（どのリモートにもまだ無いコミット）で変わったものを見ます。

| 変わったもの | フックがすること |
|---|---|
| YAML だけ | ND のプロジェクトへ取り込みます（`import --complete --prune --write-back`） |
| ND のプロジェクトだけ | YAML へ書き出します（`export --all`） |
| 両方（またはどちらも変わっていない） | 何もしません。どちらを正とするかを決めて、手でそろえてください |

そろえたときも、プッシュはいったん止まります。そろえた結果は作業コピーに残るので（コミットはしません）、中身を確かめてコミットし、もう一度プッシュしてください。差分が無いので通ります。

## 気をつけること

- 「ND のプロジェクト」は、リポジトリの中のプロジェクトファイル（`*.nproj`）・モデルユニット（`*.nmdl`）・プロファイルユニット（`*.nprof`）です（YAML のフォルダの中は除きます）。1つのリポジトリに ND のプロジェクトが1つの前提です。
- 取り込みは、YAML をプロジェクトの全部とみなします。YAML から消したモデルは、ND のプロジェクトからも消えます。コミットする前に、`git diff` や ND で中身を確かめてください。取り消すなら、止まったときに一覧に出たファイルを `git checkout -- <ファイル>` で戻します。
- ND でプロジェクトを開いたままでも止めません。取り込んだ後は、ND でプロジェクトを開き直してください（開いたまま保存すると、取り込んだ内容が上書きされます）。

## 入れ方

1. `pre-push` を、リポジトリの `.githooks/pre-push` に置きます。
2. `pre-push` の先頭の「設定」の3行（プロジェクトファイル・YAML のフォルダ・主ファイル）を、自分のリポジトリに合わせて直し、コミットします。メタモデル情報ファイルは、YAML のフォルダの `nd.metamodel.yaml` を使います。
3. 各自、クローンの後に1回だけ次を実行します。CLI のパスは PC ごとに違うので、フックには書かず、各自の git の設定に書きます（PATH に `yamlexchange` があれば、2行目は要りません）。

   ```
   git config core.hooksPath .githooks
   git config yamlexchange.cli "<yamlexchange.exe のフルパス>"
   ```

   ND に入れた YamlExchange の CLI は、`%LOCALAPPDATA%\DENSO CREATE\Next Design\installed-packages\YamlExchange.<版>\extensions\5.1\Tools\yamlexchange.exe` にあります。
